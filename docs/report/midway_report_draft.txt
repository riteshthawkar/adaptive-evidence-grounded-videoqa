Title:
Adaptive Minimal Evidence Acquisition for Grounded VideoQA

Abstract:
Video question answering (VideoQA) systems often process more context than is necessary to answer a question, which increases compute cost and makes it harder to interpret what evidence actually supports the prediction. In this project, we study grounded VideoQA as an evidence acquisition problem under a fixed budget. Starting from a multimodal candidate pool built from keyframes and short temporal video segments, we compare three strategies: a fixed-budget baseline, a keyword-based sequential policy, and a learned sequential acquisition policy. The current implementation supports end-to-end preprocessing, visual evidence materialization, CLIP-based feature extraction, oracle trace construction, and policy training. Preliminary experiments on NExT-GQA show that the learned policy can match fixed-budget accuracy while using much less evidence. On a 500-train / 200-validation setup, the learned policy achieves 0.365 accuracy with average evidence cost 1.5, compared with 0.360 accuracy and cost 7.5 for the fixed-budget baseline. These results suggest that adaptive evidence acquisition is a promising direction for reducing context usage in grounded VideoQA, although the current system still shows a tradeoff between compactness and temporal grounding quality.

1. Introduction / Background
VideoQA requires a model to answer natural-language questions about events, objects, or interactions in a video. The task is challenging because the relevant evidence is usually sparse relative to the full video. A system may need to identify a short time span, a few visually informative frames, or a small subset of temporally coherent segments rather than processing all available context uniformly.

This project is motivated by two problems in current VideoQA pipelines. First, many systems retrieve or process a fixed amount of evidence regardless of whether the question is simple or hard. Second, answer accuracy alone does not reveal whether the selected evidence is actually necessary or grounded in the correct temporal region. These issues make it difficult to build efficient and interpretable systems.

Our midway goal is therefore to formulate grounded VideoQA as adaptive evidence acquisition under a budget. Instead of always consuming the same amount of evidence, the system should decide when enough evidence has already been collected. This is especially relevant for modern retrieval-based and long-context systems, where the main bottleneck is often not model capacity but the cost of selecting, encoding, and using evidence.

The broader long-term goal of the project is to study minimal sufficient evidence: the smallest subset of evidence that preserves correct answering and, when possible, remains temporally grounded. For the midway report, we focus on building the experimental scaffold and validating the central efficiency hypothesis on NExT-GQA.

2. Related Work
Early VideoQA benchmarks such as MovieQA, TGIF-QA, and TVQA established the task and showed that multi-modal reasoning over temporal visual content is difficult. TVQA in particular highlighted the importance of localized reasoning and evidence selection. Later extensions such as TVQA+ and grounded VideoQA datasets further emphasized that correct answers should be linked to correct supporting evidence rather than treated as pure classification outputs.

More recent work moved from task-specific fusion architectures toward pretrained vision-language representations and retrieval-augmented reasoning. CLIP-style models made text-image and text-video alignment much more practical, and several later systems showed that strong VideoQA performance can be obtained by combining pretrained visual encoders with lightweight answer modules. In parallel, the rise of long-video understanding and retrieval-augmented generation shifted attention from dense full-context processing toward selective evidence construction.

The main insight from this literature is that modality-aware retrieval by itself is no longer sufficient as a contribution. The more interesting question is how much evidence is truly required, at what granularity, and under what budget. This motivates our current project direction: adaptive minimal evidence acquisition, where the system is evaluated not only on answer accuracy but also on evidence cost and temporal grounding.

3. Method
The current pipeline consists of five stages.

Stage 1: dataset normalization.
Raw dataset annotations are converted into a unified JSONL format. For NExT-GQA, the implementation reads the official CSV annotations together with optional grounding JSON, frame-time JSON, and video-id maps. This produces a consistent per-example schema with question text, answer options, answer index, temporal grounding when available, and metadata needed for later processing.

Stage 2: candidate-pool construction.
For each example, the system constructs a multimodal candidate pool. In the current NExT-GQA experiments, the main evidence sources are sampled frame candidates and short temporal segment candidates. These are generated from either frame timestamps or inferred video spans. The candidate-pool stage standardizes all evidence items into a common structure with timestamps, modality tags, retrieval scores, and acquisition costs.

Stage 3: visual evidence materialization and feature extraction.
The system materializes real frame artifacts from source videos using ffmpeg and extracts CLIP-based visual features for frames and aggregated segment features. This gives a practical multimodal retrieval space without requiring end-to-end video-language training.

Stage 4: answering and oracle construction.
We currently use a frozen multimodal answerer built on CLIP-based retrieval features. For fixed-budget evaluation, the retriever first collects a set number of items from each modality. We then build oracle traces by greedily pruning retrieved evidence while enforcing correctness and a minimum sufficiency constraint. These oracle traces serve as supervision for later policy learning.

Stage 5: sequential evidence acquisition.
The learned policy operates over four actions: acquire_subtitle, acquire_frame, acquire_segment, and stop. For the current NExT-GQA setup, subtitles are not used, so the relevant competition is between frame and segment evidence. Given the current acquired evidence and the remaining candidate pool, the policy predicts the next action. A recent bug caused the policy to degenerate by stopping immediately, but this was fixed by enforcing a minimum number of acquired items before stop is allowed. This fix is important because it converts the policy from a trivial zero-evidence predictor into a meaningful acquisition model.

4. Experiments and Preliminary Results
Dataset.
We currently report real experiments on NExT-GQA. This benchmark is suitable for a midway checkpoint because it supports grounded VideoQA and allows us to test the complete retrieval and evidence-acquisition pipeline on real videos. For the current checkpoint, we use a 500-example training subset and a 200-example validation subset.

Compared methods.
We evaluate three systems:
- Fixed-budget baseline: retrieve 3 frames and 3 segments, then answer with the frozen multimodal answerer.
- Keyword sequential policy: a heuristic policy baseline that effectively consumes the same fixed allocation in this setup.
- Learned sequential policy: a trainable linear policy over acquisition states, trained from oracle traces derived from the frozen multimodal answerer.

Evaluation metrics.
We report:
- accuracy
- selected evidence cost
- selected evidence count
- selected temporal IoU

These metrics capture the main tradeoff of interest: answer quality versus evidence efficiency, while still preserving a grounding signal.

Preliminary quantitative results.

Table 1. NExT-GQA preliminary results on the 500 / 200 setup.

Method                         Accuracy    Evidence Cost    Evidence Count    Temporal IoU
Fixed-budget baseline          0.360       7.5              6.0               0.273
Keyword sequential policy      0.360       7.5              6.0               0.273
Learned sequential policy      0.365       1.5              1.0               0.168

Interpretation.
The fixed-budget and keyword-policy baselines behave identically in the current setup, which indicates that the heuristic policy is not providing useful selectivity here. The main result is the learned policy. It slightly improves validation accuracy from 0.360 to 0.365 while reducing the average evidence cost from 7.5 to 1.5 and the average evidence count from 6.0 to 1.0. In other words, the learned policy preserves or slightly improves answer quality while using only about 20% of the evidence cost.

This is an encouraging signal for the project’s main hypothesis. It suggests that adaptive evidence acquisition can make the VideoQA pipeline substantially more efficient. At the same time, temporal IoU drops from 0.273 to 0.168, which indicates a nontrivial tradeoff between answer efficiency and grounding quality. This is a useful scientific result rather than a failure, because it highlights that accuracy, evidence compactness, and grounding do not automatically improve together.

Stability across seeds.
We also aggregated the 500 / 200 experiment over three seeds (13, 21, 34). All three methods produced identical or effectively identical results in this setup, leading to zero standard deviation in the current table. While this is plausible for a deterministic or low-capacity policy setting, it also suggests that the current model family is still relatively simple. This reinforces the need for larger-scale experiments and stronger answerer backends in the next project stage.

Implementation and debugging progress.
An important part of the midway progress is the successful construction of a complete and reproducible experimental scaffold. During development we identified and fixed several real bugs that would have made large experiments unreliable, including:
- ffmpeg failures caused by odd-sized video frames during segment extraction
- frame requests near the end of videos that produced missing image files
- degenerate policy behavior that stopped before acquiring any evidence

This engineering progress matters for the coursework because the midway checkpoint is intended to show that a real method has been applied and evaluated, not only proposed conceptually.

5. Discussion and Future Work
The project is now strong enough for a midway checkpoint, but several limitations remain. First, the strongest implemented answerer is still a frozen multimodal scorer rather than a stronger fine-tuned VLM-style model. Second, the learned policy operates at modality level and always selects the top remaining item within the chosen modality; it does not yet perform richer within-modality reranking. Third, the current evidence-efficiency gain comes with reduced temporal grounding overlap, so the next stage must study this tradeoff more carefully.

The immediate next steps are:
- scale the NExT-GQA experiments from 500 / 200 to larger and then full train/validation settings
- add oracle-validity reporting and more detailed policy analysis
- inspect per-example acquisition traces to understand when the policy prefers a single segment versus a single frame
- extend the evaluation to TVQA or TVQA+ for a subtitle-aware setting
- add a stronger answerer backend so that minimal-evidence claims are less dependent on a lightweight frozen baseline

At this midway stage, the most defensible conclusion is the following: the project has progressed from a conceptual idea into a functioning grounded VideoQA pipeline with real retrieval, real evidence extraction, and preliminary evidence-efficiency results. That is sufficient for a solid coursework midway report, and it also provides a clear path toward the final report.
